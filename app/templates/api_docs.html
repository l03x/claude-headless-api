Every completion is produced by running Claude Code in headless mode (claude -p) on this server, behind an OpenAI-compatible interface: point any OpenAI SDK at {{ base_url }}/v1 and it works. Claude runs with no tools, so it behaves like a plain text model.

Quickstart

  1. Ask an administrator for an API token (created under API tokens in the dashboard). It looks like chk_….
  2. Send a chat completion. With the official SDKs, only base_url and api_key change.

Authentication

Every /v1 endpoint needs a token, sent as Authorization: Bearer <token> or x-api-key: <token>. A token belongs to a user and may carry restrictions set by the administrator:

  • Expiry — after it, requests fail with 401 api_key_expired.
  • Allowed models — other models fail with 403 model_not_allowed; GET /v1/models lists only the allowed ones.
  • Maximum effort — higher efforts fail with 403 effort_not_allowed.
  • Rate limit — requests per minute; beyond it, 429 rate_limit_exceeded.
{{ code_tabs(guide.auth) }}

Models & effort

model is passed to claude --model: an alias (opus, sonnet, haiku, fable) always means the latest model of that family, or use a full id such as claude-sonnet-5-5. Omit it to use the server's default.

effort is passed to claude --effort and controls how long Claude thinks:

EffortUse it for
lowQuick answers, classification, extraction. Fastest and cheapest.
mediumEveryday questions and writing.
highReasoning, code, multi-step problems.
xhighHard problems that benefit from long deliberation.
maxThe hardest problems, regardless of time and cost.

OpenAI's reasoning_effort is accepted too (none and minimal map to low). If both are sent, effort wins.

Sessions

A stateless chat completion re-sends the whole conversation every time. A session keeps it on the server instead: the first turn starts a Claude Code session and each later turn resumes it, so you send only the new message and Claude reuses its prompt cache.

  • Create one with POST /v1/sessions, then talk with POST /v1/sessions/{id}/messages.
  • Or, from an OpenAI SDK, pass session_id in the request body: "new" starts one, an existing id continues it.
  • The system prompt is fixed per session; model and effort can change on any turn.
  • Sessions belong to your user: all of your tokens can use them, nobody else's can. Turns in one session run one at a time.
{{ code_tabs(guide.sessions) }}

Streaming

Send "stream": true to receive the reply as it is written, as OpenAI-style server-sent events: data: lines holding chat.completion.chunk objects (text in choices[0].delta.content), then data: [DONE]. It works on chat completions (with or without session_id) and on session messages.

  • "stream_options": {"include_usage": true} adds a final chunk with usage.
  • Errors before any text are ordinary JSON error responses; an error after text has started arrives as one data: {"error": …} event, with no [DONE].
  • Disconnecting stops the run. An interrupted session turn is not stored.
{{ code_tabs(guide.streaming) }}

401missing_api_key, invalid_api_key, api_key_revoked, api_key_expiredThe token is missing or unusable.
403user_disabled, model_not_allowed, effort_not_allowedThe token may not do this.

Limits & unsupported features

  • Text only — image, audio and file inputs are rejected.
  • No tool / function calling — Claude runs without tools.
  • Sampling controls are ignored — temperature, top_p, max_tokens, stop, seed, n, … are accepted but have no effect.
  • Usage includes Claude Code's own context, so prompt_tokens is larger than the text you sent.

The full list, with what it would take to add each feature, is in docs/missing-features.md in the repository.
